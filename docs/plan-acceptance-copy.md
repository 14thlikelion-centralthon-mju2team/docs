## 1. 계산 근거 문구 (PRD §8.5 형식 고정)

계획 상세를 펼치면 아래 5개 항목이 **항상 이 순서**로 나온다. 값이 0이거나 해당 없으면 항목 자체를 숨긴다(빈 줄로 보여주지 않는다).

| 항목 | 출처(`reasons[].source`) | 문구 템플릿 | 예시 |
|---|---|---|---|
| 개인 준비 시간 | `estimate` | "개인 준비 시간 {n}분: 최근 {count}회 기록 기준, 초기 설정보다 {+/-m}분" | "개인 준비 시간 35분: 최근 8회 기록 기준, 초기 설정보다 +5분" |
| 등록 루틴 | `prepRule` | "{항목명} ({등록한 루틴/준비물})" | "렌즈·화장 (등록한 루틴)" |
| 이동 시간 | `routeProvider` | "이동 시간 {n}분: 외부 지도 API 기준" | "이동 시간 42분: 외부 지도 API 기준" |
| 도착 여유 | 고정값 | "도착 여유 {n}분" | "도착 여유 10분" |
| 환경 가산 | `environment` | "{원인}로 인한 추가 준비 {n}분" | "비로 인한 추가 준비 5분" |

**보정이 처음 일어난 경우(신규 사용자, 표본 3회 미만)**: "아직 학습 중이에요 — 처음 입력한 준비 시간을 기준으로 계산했어요"로 대체. 존재하지 않는 학습 이력을 있는 것처럼 쓰지 않는다.

## 2. 상태별 화면 문구 — 데이터 부족 · 계획 불가능 · 사용자 수정

PRD §10.2 상태 메시지 표(여유/준비시작/출발임박/촉박/웰니스)는 `docs/product-contract.md`에서 이미 고정. 이 문서는 **그 표에 없는 예외 상태**만 다룬다.

| 상태 | 트리거 | 메인 문구 | 보조 문구 |
|---|---|---|---|
| 경로 조회 실패 (마지막 값 재사용) | `degraded: route_stale` | (기존 상태 메시지 유지) | "최신 교통 정보를 가져오지 못했어요 · {HH:mm} 기준" |
| 환경 데이터 없음 | `degraded: env_unavailable` | (기존 상태 메시지 유지, 웰니스 영역만 생략) | 문구 없음 — 조용히 생략, 오류 표시 금지 |
| 준비 시간 시드 없음("잘 모르겠어요") | `degraded: seed_missing` | (기존 상태 메시지 유지) | "아직 준비 시간을 몰라서 평균값으로 계산했어요" |
| **계획 불가능** (`feasible: false`) | 지금 출발해도 목표 도착 불가 | "지금 출발해도 조금 늦을 수 있어요" | "가장 빠른 경로로 다시 계산했어요. 그래도 괜찮다면 그대로 진행할게요" |
| 다음 일정 없음 | 관리 대상 일정 0건 | "관리할 다음 일정이 없어요" | "일정을 만들거나 지도에서 장소를 검색해 보세요" [일정 만들기] [지도 검색] |
| 오프라인 | 네트워크 끊김 | (마지막 계획 그대로 표시) | "마지막으로 확인한 계획이에요 · {HH:mm} 기준" |
| 종일 일정(계획 대상 제외) | `startsAt` 없이 날짜만 | 계획 카드 자체를 노출하지 않음 | — |

**"계획 불가능" 문구 원칙**: "지금 출발해도 늦어요"처럼 단정·질책하는 표현 대신 "조금 늦을 수 있어요"로 완충한다. 앱이 사용자를 다그치는 것이 아니라 상황을 보고한다는 톤을 유지한다(PRD §8.7 — 질책도 건강 판단도 하지 않는다).

## 3. 사용자 수정 시나리오 인수 조건

| 시나리오 | 완료 조건 |
|---|---|
| 준비/출발 시각 직접 수정 | 수정 즉시 새 계획 리비전 생성, 근거 문구도 "직접 수정한 값"으로 갱신 표시 |
| 경로 변경 | 선택 즉시 재계산되어 3개 시각·근거·체크리스트 모두 갱신. 화면 깜빡임 없이 반영 |
| 출발지 변경 | 이동 시간·교통 버퍼 재계산, "이동 시간 {n}분: 외부 지도 API 기준" 문구 자동 갱신 |
| 이번 일정 제외 | 확인 없이 즉시 제외(가벼운 취소는 되돌리기 스낵바로 처리, 확인 모달 금지) |
| 맞춤 준비 항목 추가("이번 일정만"/"기본 항목으로 저장") | 선택에 따라 이번 계획에만 반영되는지, 향후 모든 일정에 반영되는지 라벨로 명확히 구분 표시 |

## 4. 화면별 완료 조건 (product-contract.md §2 보강)

- **홈 카드**: 계산 근거 펼침 상태에서 위 §1 표의 항목이 실제 API 응답(`reasons[]`)과 1:1로 매핑되어 보인다. 순서 임의 변경 금지.
- **일정 상세**: `feasible: false`일 때 §2 문구가 뜨고, 그 아래 "그래도 이 시각으로 진행" 버튼이 있어 사용자가 최종 결정한다(앱이 임의로 계획을 취소하지 않는다).
- 모든 화면: 진행 중(로딩) 상태에서 이전 계획 값이 사라지지 않고 유지된 채 갱신된다(빈 화면 깜빡임 금지).
